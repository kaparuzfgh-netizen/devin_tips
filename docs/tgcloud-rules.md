# Правила платформы Telegram Serverless (tgcloud) — на чём ломаются

Полный справочник API — `tgcloud-sdk.md` в этой же папке. Ниже — то, на чём
этот проект ломался или ломается чаще всего.

## Модули
- Свои модули импортируй по относительному пути **с `.js`**: `import { users } from '../schema.js'`.
- SDK — по имени: `import { db, api, fetch } from 'sdk'`, `import { eq, sql } from 'sdk/db'`.
- Нет файловой системы и нет npm-пакетов в рантайме. Из `tgcloud/` недоступно ничего снаружи.
- `export default` хендлера получает payload апдейта (для `handlers/message` — это `Message`);
  полный `Update` — во втором аргументе `ctx.update`.

## База данных
- Каждый вызов БД асинхронный — всегда `await`.
- Внешних ключей нет (`.references()` падает при объявлении). Целостность — в коде: сначала дети, потом родители.
- Таблицы и колонки удаляются только через `.deprecated('причина')`; удаление объявления ничего не дропает.
- Смена типа колонки — вручную через `db.run(...)`.
- Колонки `mode: 'timestamp'` ожидают `Date`, а не число (см. KI-004/B4).

## Bot API
- `api.<method>({...})` возвращает уже распакованный результат и **бросает `BotApiError`**
  (`.code`, `.description`, `.parameters`). Оборачивай вызовы в `try/catch` и логируй эти три поля.
- В Bot API параметр называется `chat_id`, в JS-переменных — `chatId`. Шортхенд `{ chat_id }`
  внутри функции — краш `ReferenceError` (подтверждено: KI-002, все админ-команды).
- Каждый хендлер: общий `try/catch` + `console.log` с именем хендлера и ключевыми входными
  данными (без токенов и секретов). Не удаляй существующие.

## Логи и деплой
- В боевом режиме `console.log` не виден (KI-001) — виден только при `npx tgcloud run`.
  Ошибки админских действий показывай админу в чате через `BotApiError` (`.code`, `.description`).
- `push` код не трогает БД. Изменили `schema.js` → после `push` нужен отдельный `npx tgcloud migrate`.
- Проверка без Telegram: `npx tgcloud run <module> '<json>'`.
- Состояние: `npx tgcloud status`; вебхук: `npx tgcloud webhook`.
