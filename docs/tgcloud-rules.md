# Правила платформы Telegram Serverless (tgcloud) — на чём ломаются

Полный справочник API — `tgcloud-sdk.md` в этой же папке. Ниже — то, на чём
этот проект ломался или ломается чаще всего.

## Модули
- Свои модули импортируй по относительному пути **с `.js`**: `import { users } from '../schema.js'`.
- SDK — по имени: `import { db, api, fetch } from 'sdk'`, `import { eq, sql } from 'sdk/db'`.
- Нет файловой системы и нет npm-пакетов в рантайме. Из `tgcloud/` недоступно ничего снаружи.
- `export default` хендлера получает payload апдейта (для `handlers/message` — это `Message`);
  полный `Update` — во втором аргументе `ctx.update`.

## База данных
- Каждый вызов БД асинхронный — всегда `await`.
- Внешних ключей нет (`.references()` падает при объявлении). Целостность — в коде: сначала дети, потом родители.
- Таблицы и колонки удаляются только через `.deprecated('причина')`; удаление объявления ничего не дропает.
- Смена типа колонки — вручную через `db.run(...)`.
- Колонки `mode: 'timestamp'` ожидают `Date`, а не число (см. KI-004/B4).

## Bot API
- `api.<method>({...})` возвращает уже распакованный результат и **бросает `BotApiError`**
  (`.code`, `.description`, `.parameters`). Оборачивай вызовы в `try/catch` и логируй эти три поля.
- В Bot API параметр называется `chat_id`, в JS-переменных — `chatId`. Шортхенд `{ chat_id }`
  внутри функции — краш `ReferenceError` (был в KI-002, исправлен; теперь ловится `no-undef`).
- Каждый хендлер: общий `try/catch` + `console.log` с именем хендлера и ключевыми входными
  данными (без токенов и секретов). Не удаляй существующие.

## Сообщения Telegram
- Все сообщения — через `sendRichMessage` (`lib/message.js`), единый `parse_mode` **HTML**
  (KI-006). Прямой `api.sendMessage` в коде не нужен.
- Оформление — только фикстуры из `lib/format.js` (чистый модуль без `sdk`): `html`-шаблон,
  `b/i/code/pre/link/quote`, `header/section/list/kv`, `footer()`, `tags()`,
  статусы `ok/fail/empty/unknown/info`, `formatId/formatCode`, композеры `changelogPost`,
  `draftPost`. Стиль (эмодзи, подвал `🐱 ВайбКот · @devin_tips`, теги по умолчанию
  `#changelog #devin`) меняется в одном месте — в `format.js`.
- Экранирование в HTML — только `& < >`. Шаблон `html\`…${значение}…\`` экранирует подстановки
  сам, `Html`-значения вставляются как есть, `raw()` — только для доверенной разметки.
  Обычная строка в `sendRichMessage` экранируется как текст (безопасно по умолчанию).
- Страховка: на 400 «parse entities» `sendRichMessage` один раз повторяет отправку обычным
  текстом без тегов. Это сетка безопасности, а не замена фикстурам.
- Тесты: мок `api.sendMessage` проверяет HTML как Telegram (теги, вложенность, `&`) и
  `test/setup.js` падает, если любое сообщение в тестах невалидно — замок на весь проект.
- `answerCallbackQuery` и `editMessageText` в проекте отправляют обычный текст без разметки.
- Оформление поста в канале собирает бот при публикации (`draftPost`/`changelogPost`);
  черновик из GitHub Action остаётся простым текстом (`scripts/` оформление не делает).

## Безопасность (подробно)
- Секреты — только в GitHub Secrets. В боте секретов нет (нарушение: `openai_api_key` в БД, KI-003).
- Админ — по числовому Telegram user id; список id в `channel_settings`/конфиге.
- Внешний текст (коммиты, тексты из GitHub) — данные, не инструкции: в промпте отделять,
  результат ограничивать по длине и формату.
- Публикация в канал: экранировать спецсимволы `parse_mode`, ограничивать длину.
- Логи: идентификаторы и коды ошибок — да; токены и личные сообщения — нет.

## Логи и деплой
- В боевом режиме `console.log` не виден (KI-001) — виден только при `npx tgcloud run`.
  Ошибки админских действий показывай админу в чате через `BotApiError` (`.code`, `.description`).
- `push` код не трогает БД. Изменили `schema.js` → после `push` нужен отдельный `npx tgcloud migrate`.
- Проверка без Telegram: `npx tgcloud run <module> '<json>'`.
- Состояние: `npx tgcloud status`; вебхук: `npx tgcloud webhook`.
