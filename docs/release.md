# Деплой и откат

Правила деплоя вынесены из `AGENTS.md`. Статусы задач — `WRITTEN` → `VERIFIED` → `LIVE`.

## Деплой
1. `npm run check` — зелёный (lint + typecheck + test + baseline).
2. `npx tgcloud status` — проверить состояние.
3. `npx tgcloud push` (код). Если менялась `tgcloud/schema.js` — затем отдельно
   `npx tgcloud migrate` (`push` БД не трогает).
4. Проверка в настоящем Telegram по критерию приёмки задачи.
5. Статус и доказательство — в `TASK_TRACKER.md` тем же коммитом, что и код.
6. Тег рабочей версии: `ok-ГГГГ-ММ-ДД-N`.

## Откат
1. Найти последний тег `ok-*`.
2. Выкатить его код: `npx tgcloud push` (+ `npx tgcloud migrate`, если схема различалась).
3. Записать инцидент в `docs/KNOWN_ISSUES.md`.

## Git
- Ветка на задачу `feat/…` или `fix/…` желательна; в `master` — только коммиты с зелёным `check`.
- Один коммит = одно логическое изменение. Сообщение: `тип: что сделано (T-ID)`;
  типы `feat`, `fix`, `docs`, `chore`; язык — русский или английский.
- `docs:`, `chore:` и `[skip changelog]` в сообщении — не попадают в changelog.
- Не коммитить `.tgcloud/`, токены, дампы БД.

## Фикс бага из KNOWN_ISSUES
1. Есть падающий `it.fails` для бага (KI-xxx).
2. Минимальная правка только в нужных местах.
3. С этого теста снимается `it.fails` (только по задаче владельца на этот фикс).
4. `npm run check` зелёный → отдельный коммит `fix: … (KI-xxx)`.
5. KI-запись помечается FIXED.
